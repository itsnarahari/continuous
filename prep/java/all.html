Both CrudRepository and JpaRepository are used in Spring Data JPA, but they have key differences.

🔹 CrudRepository (Basic CRUD Operations)

  • Provides basic save(), findById(), delete(), exists(), etc.
  • Suitable for simple CRUD operations.
  • Does NOT provide JPA-specific features like pagination or batch operations.

🔹 JpaRepository (Extended JPA Features)

  • Extends CrudRepository and PagingAndSortingRepository.
  • Provides additional methods like flush(), saveAndFlush(), findAll(Pageable pageable).
  • Supports batch operations and pagination.

💡 Example:


        import org.springframework.data.repository.CrudRepository;
        import org.springframework.data.jpa.repository.JpaRepository;
        import java.util.List;

        // Using CrudRepository
        public interface EmployeeCrudRepo extends CrudRepository<Employee, Long> {
            List<Employee> findByName(String name); // Custom query
        }

        // Using JpaRepository
        public interface EmployeeJpaRepo extends JpaRepository<Employee, Long> {
            List<Employee> findByName(String name);
        }

🔹 When to Use What?

  • Use CrudRepository when you need only basic CRUD operations.
  • Use JpaRepository when you need batch updates, pagination, or JPA-specific features.

SpringApplication.run() is the entry point of a Spring Boot application. It initializes the application context, loads beans, and starts the embedded server.

🔹 Steps Performed Internally:

  1. Creates a SpringApplication instance: Determines if it's a web application.
  2. Configures environment: Loads properties from `application.properties` or `application.yml`.
  3. Loads Initializers: Calls `ApplicationContextInitializer` beans.
  4. Loads Listeners: Registers event listeners (e.g., `ApplicationListener`).
  5. Creates ApplicationContext: Loads the appropriate context (`AnnotationConfigServletWebServerApplicationContext` for web apps).
  6. Refreshes the ApplicationContext: Initializes all beans and configurations.
  7. Calls CommandLineRunners and ApplicationRunners: Executes additional startup logic.
  8. Starts the embedded server: (Tomcat, Jetty, etc., for web applications).

💡 Example:


        import org.springframework.boot.SpringApplication;
        import org.springframework.boot.autoconfigure.SpringBootApplication;

        @SpringBootApplication
        public class MySpringBootApplication {
            public static void main(String[] args) {
                SpringApplication.run(MySpringBootApplication.class, args);
            }
        }

🔹 Equivalent Manual Steps (Without SpringApplication.run()):


        import org.springframework.context.annotation.AnnotationConfigApplicationContext;

        public class ManualSpringBoot {

💡 Why use SpringApplication.run()?

  • Encapsulates all **boilerplate startup logic**.
  • Handles **environment setup, listeners, and context refresh** automatically.

🔹 HashMap is a key-value data structure based on hashing. It provides O(1) average time complexity for insert, search, and delete operations.

📌 HashMap Data Structure:

  • Internally, it is an **array of Node** (buckets).
  • Each bucket stores **a linked list** (before Java 8) or **a balanced tree** (after Java 8, when collisions exceed a threshold).

🔹 Important Components:

  • Capacity: Initial size of the HashMap (default: 16).
  • Load Factor: Default 0.75 (resizing occurs when 75% of the map is full).
  • Threshold: `capacity * load factor`, determines when resizing happens.

🔹 Internal Working of `put(K, V)`:

  1. Computes hashCode() of the key.
  2. Uses (hashCode % capacity) to find the index.
  3. If bucket is empty, stores the new entry.
  4. If a collision occurs, it stores the entry as:
    • 🔹 **Linked List** (before Java 8).
    • 🔹 **Balanced Tree (Red-Black Tree)** (after Java 8, if the chain length > 8).
  5. Resizes the HashMap if the threshold is reached.

🔹 Example of HashMap Implementation:


        import java.util.HashMap;

        public class HashMapExample {
            public static void main(String[] args) {
                HashMap map = new HashMap<>();
                map.put("Alice", 25);
                map.put("Bob", 30);
                map.put("Charlie", 35);
                
                System.out.println("Age of Bob: " + map.get("Bob")); // 30
            }
        }

🔹 How `get(K)` Works?

  • Computes the **hashCode()** of the key.
  • Finds the bucket using `(hashCode % capacity)`.
  • Traverses the linked list or tree to find the key.
  • Returns the value if found, else returns `null`.

🔹 HashMap Performance Optimization:

  • Use a good hash function to minimize collisions.
  • Set an **optimal initial capacity** to reduce resizing overhead.
  • Keep **load factor at 0.75** for the best trade-off between performance and memory usage.

🔹 `Map` is an interface in Java that provides a key-value store.

📌 Different Implementations of `Map`:

  • 🔹 HashMap → Uses **array + linked list + red-black tree**.
  • 🔹 TreeMap → Uses **Red-Black Tree** (sorted order).
  • 🔹 LinkedHashMap → Uses **Doubly Linked List** (preserves insertion order).
  • 🔹 ConcurrentHashMap → Uses **Segmented Locks for thread safety**.

🔹 How Does `HashMap` Work Underneath?

  • Stores data in an array of Node<K, V>.
  • Uses hashCode() and (hash % capacity) to find bucket.
  • Handles **collisions using Linked List (before Java 8)** and **Red-Black Tree (after Java 8, if needed).**

🔹 Example of `HashMap`:


        import java.util.HashMap;

        public class HashMapExample {
            public static void main(String[] args) {
                HashMap map = new HashMap<>();
                map.put("Alice", 25);
                map.put("Bob", 30);
                map.put("Charlie", 35);
                
                System.out.println("Age of Bob: " + map.get("Bob")); // 30
            }
        }

🔹 How Does `TreeMap` Work Underneath?

  • Stores data in a Red-Black Tree (Self-balancing Binary Search Tree).
  • Keeps **keys sorted in natural or custom order**.
  • O(log n) complexity for insert/search.

🔹 Example of `TreeMap`:


        import java.util.TreeMap;

        public class TreeMapExample {
            public static void main(String[] args) {
                TreeMap map = new TreeMap<>();
                map.put("Alice", 25);
                map.put("Bob", 30);
                map.put("Charlie", 35);
                
                System.out.println("First Entry: " + map.firstEntry()); // Alice=25
            }
        }

🔹 How Does `ConcurrentHashMap` Work?

  • Uses **segment-based locking** (before Java 8) and **CAS (Compare-And-Swap)** (after Java 8).
  • Provides **thread-safe** operations with **high performance**.

🔹 Example of `ConcurrentHashMap`:


        import java.util.concurrent.ConcurrentHashMap;

        public class ConcurrentHashMapExample {
            public static void main(String[] args) {
                ConcurrentHashMap map = new ConcurrentHashMap<>();
                map.put("Alice", 25);
                map.put("Bob", 30);

                System.out.println("Alice's Age: " + map.get("Alice"));
            }
        }

🔹 Summary of `Map` Implementations:

Type Data Structure Sorting Thread Safety
HashMap Array + Linked List + Red-Black Tree No No
TreeMap Red-Black Tree Yes No
LinkedHashMap Linked List + HashMap No No
ConcurrentHashMap Bucket-based HashMap No Yes

🔹 What is Circular Dependency?

🔄 A **circular dependency** occurs when two or more beans depend on each other, causing a loop.

📌 Example of Circular Dependency


      @Component
      public class A {
          private final B b;

          @Autowired
          public A(B b) {
              this.b = b;
          }
      }

      @Component
      public class B {
          private final A a;

          @Autowired
          public B(A a) {
              this.a = a;
          }
      }

🛑 **Problem:** When Spring tries to instantiate A, it needs B, which again needs A, causing a cycle.

🔹 How to Fix Circular Dependency?

📌 1️⃣ Use @Lazy Annotation

🔄 Spring will **delay bean initialization** until it's needed.


      @Component
      public class A {
          private final B b;

          @Autowired
          public A(@Lazy B b) {
              this.b = b;
          }
      }

📌 2️⃣ Use Setter Injection Instead of Constructor Injection

🔄 Spring will first instantiate the beans and then set dependencies.


      @Component
      public class A {
          private B b;

          @Autowired
          public void setB(B b) {
              this.b = b;
          }
      }

📌 3️⃣ Use ObjectFactory or Provider from javax.inject

🔄 **Lazily loads dependencies** only when required.


      @Component
      public class A {
          private final Provider bProvider;

          @Autowired
          public A(Provider bProvider) {
              this.bProvider = bProvider;
          }

          public void someMethod() {
              B b = bProvider.get(); // Gets B when needed
          }
      }

📌 4️⃣ Refactor Code to Break Circular Dependency

🔄 **Introduce a third class** to manage dependencies.


      @Component
      public class Mediator {
          private final A a;
          private final B b;

          @Autowired
          public Mediator(A a, B b) {
              this.a = a;
              this.b = b;
          }
      }

✅ Summary

  • ✔ Circular dependency happens when two beans depend on each other.
  • ✔ Solutions include **@Lazy, setter injection, Provider, and refactoring code**.
  • ✔ The best practice is to **avoid circular dependencies** by **designing components properly**.

**Inter-thread communication** in Java is a mechanism that allows synchronized threads to communicate with each other. It helps avoid busy waiting and improves performance.

1️⃣ **Methods for Inter-Thread Communication**

  • wait() - Causes the current thread to wait until another thread notifies it.
  • notify() - Wakes up a single thread waiting on the same object's monitor.
  • notifyAll() - Wakes up all threads waiting on the same object's monitor.

2️⃣ **Example of Inter-Thread Communication using wait() & notify()**


class SharedResource {
    private int data;
    private boolean available = false;

    public synchronized void produce(int value) {
        while (available) { 
            try { wait(); } catch (InterruptedException e) { e.printStackTrace(); }
        }
        data = value;
        System.out.println("Produced: " + data);
        available = true;
        notify();  // Notify consumer
    }

    public synchronized void consume() {
        while (!available) { 
            try { wait(); } catch (InterruptedException e) { e.printStackTrace(); }
        }
        System.out.println("Consumed: " + data);
        available = false;
        notify(); // Notify producer
    }
}

class Producer extends Thread {
    SharedResource resource;
    Producer(SharedResource resource) { this.resource = resource; }

    public void run() {
        for (int i = 1; i <= 5; i++) {
            resource.produce(i);
        }
    }
}

class Consumer extends Thread {
    SharedResource resource;
    Consumer(SharedResource resource) { this.resource = resource; }

    public void run() {
        for (int i = 1; i <= 5; i++) {
            resource.consume();
        }
    }
}

public class InterThreadCommunicationExample {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();
        new Producer(resource).start();
        new Consumer(resource).start();
    }
}

3️⃣ **How it Works?**

  • The **Producer** thread produces data and then calls `notify()` to wake up the **Consumer**.
  • The **Consumer** thread waits (`wait()`) until new data is available and then processes it.
  • After consuming, it calls `notify()` to wake up the **Producer** again.

✅ Best Practices: Always call `wait()`, `notify()`, and `notifyAll()` inside a synchronized block to avoid race conditions.

To generate a custom ID format like 2024ABCD1112A4 in Spring Boot, you need a custom ID generator. This involves:

  • Creating a custom Hibernate ID generator
  • Applying it to your entity
  • Generating structured, unique IDs

1️⃣ Custom ID Generator Class:


import org.hibernate.engine.spi.SharedSessionContractImplementor;
import org.hibernate.id.IdentifierGenerator;
import java.io.Serializable;
import java.time.Year;
import java.util.Random;

public class CustomIdGenerator implements IdentifierGenerator {
    @Override
    public Serializable generate(SharedSessionContractImplementor session, Object object) {
        String year = String.valueOf(Year.now().getValue());
        String randomLetters = generateRandomLetters(4);
        String randomNumbers = String.valueOf(1000 + new Random().nextInt(9000));
        String lastLetter = generateRandomLetters(1);
        return year + randomLetters + randomNumbers + lastLetter;
    }

    private String generateRandomLetters(int length) {
        String alphabet = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
        StringBuilder result = new StringBuilder();
        Random random = new Random();
        for (int i = 0; i < length; i++) {
            result.append(alphabet.charAt(random.nextInt(alphabet.length())));
        }
        return result.toString();
    }
}

2️⃣ Apply to Your Entity:


import jakarta.persistence.*;
import org.hibernate.annotations.GenericGenerator;

@Entity
public class User {
    @Id
    @GeneratedValue(generator = "custom-id")
    @GenericGenerator(name = "custom-id", strategy = "com.example.CustomIdGenerator")
    private String id;
    
    private String name;
    private String email;
}

import java.time.Year;
import java.util.Random;

        StringBuilder result = new StringBuilder();

            result.append(alphabet.charAt(random.nextInt(alphabet.length())));
        }
        return result.toString();
    }
}

  • Ensures unique IDs with a structured format.
  • Predictable sequence numbers from the database.
  • Readable and structured primary keys.

PermGen vs Metaspace in Java:

  • PermGen (Permanent Generation): - Used before Java 8 to store **class metadata**, method details, and interned strings. - Had a **fixed max size** (`-XX:MaxPermSize`), leading to OutOfMemoryError: PermGen Space.
  • Metaspace: - Introduced in Java 8 to **replace PermGen**. - Uses **native memory** instead of JVM heap, so it **grows dynamically**. - Controlled via -XX:MaxMetaspaceSize (optional limit).

Key Differences:

Feature PermGen (Java 7 & Before) Metaspace (Java 8+)
Storage JVM Heap (Fixed) Native Memory (Dynamic)
Size Limit Limited (-XX:MaxPermSize) Unlimited (unless restricted with -XX:MaxMetaspaceSize)
OutOfMemoryError Frequent if full Less common
Performance Slower due to heap constraints Faster due to native memory usage

Example: Metaspace Memory Leak


        import java.util.ArrayList;
        import java.util.List;

        public class MetaspaceLeakExample {
            public static void main(String[] args) {
                List classLoaders = new ArrayList<>();
                try {
                    while (true) {
                        classLoaders.add(new CustomClassLoader());
                    }
                } catch (OutOfMemoryError e) {
                    System.out.println("Metaspace OutOfMemoryError!");
                }
            }

            static class CustomClassLoader extends ClassLoader { }
        }

How to Set Metaspace Limit?


        java -XX:MaxMetaspaceSize=256m -jar myapp.jar

Conclusion:

  • PermGen was removed in Java 8 because it caused memory limitations.
  • Metaspace **uses native memory**, making it more flexible and efficient.
  • To prevent excessive growth, you can **limit Metaspace manually**.

Metaspace is managed by both the JVM and the OS. Below are the key components responsible for its control:

  • JVM's Memory Manager: Requests memory from the OS and manages allocation/deallocation based on class loading/unloading.
  • OS Memory Management: Since Metaspace is outside the heap, the OS manages its actual allocation.
  • Class Loader & Garbage Collector: JVM removes unused class metadata when classes become unreferenced.

How to Control Metaspace Growth?


      # Set a max limit for Metaspace
      java -XX:MaxMetaspaceSize=256m -jar myapp.jar

      # Enable garbage collection for class unloading
      java -XX:+UseG1GC -XX:+ClassUnloadingWithConcurrentMarkSweep

Key Takeaways:

  • ✅ JVM requests and manages Metaspace.
  • ✅ OS provides the required native memory.
  • ✅ Application Code can impact Metaspace by controlling class loading/unloading.

No, Metaspace does not store all memory areas like the heap, stack, or method area. Here’s how it fits in the JVM memory model:

📌 What does Metaspace store?
  • Class Metadata: Information about loaded classes, including methods, fields, and bytecode.
  • Runtime Constant Pool: Stores constants from class files (e.g., string literals).
  • Class Method Data: Metadata about methods but not the actual method code.
  • Reflection Objects: Metadata for reflection-based operations.
❌ What Metaspace does NOT store?
  • Heap (Objects & Data): Stored in the Young & Old Generation of Heap.
  • Stack (Threads' Execution Context): Stored in the JVM Stack Memory.
  • Method Code Execution: Stored in Code Cache (for JIT-compiled code).
📝 JVM Memory Breakdown
  • Heap: Stores objects & data.
  • Stack: Stores method call frames & local variables.
  • Metaspace: Stores class metadata.
  • Code Cache: Stores compiled machine code from JIT.
  • Direct Memory: Used by NIO buffers.
🏆 Example: Configuring Metaspace in JVM

        java -XX:MaxMetaspaceSize=256m -jar myapp.jar

This limits the maximum size Metaspace can grow.

✅ Conclusion

Metaspace only handles class metadata, while the heap, stack, and method area are managed separately by the JVM.
