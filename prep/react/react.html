📌 1. What is the Virtual DOM?

The Virtual DOM (VDOM) is a lightweight, in-memory representation of the real DOM. React uses it to improve performance by reducing direct DOM manipulation.

It's like a blueprint of the actual UI elements.

📌 2. Why is Virtual DOM Needed?
  • ⚡ Updating the real DOM is slow (it's an expensive operation)
  • 🧠 Virtual DOM allows React to batch updates efficiently
  • 🎯 It minimizes the number of changes made to the real DOM
📌 3. How It Works (Step-by-Step)
  1. React renders components to the Virtual DOM
  2. It compares the new Virtual DOM with the previous one (using diffing algorithm)
  3. It calculates the minimum set of changes needed
  4. It efficiently updates the real DOM in one go (called reconciliation)
📌 4. Code Example

Consider this simple React component:


function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count is: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

When you click the button, only the count text (`<p>`) is updated in the real DOM — not the whole UI.

Real DOM Virtual DOM
Updates are slow Updates are fast

📌 6. Visualization

Let's say you have this DOM:


<ul>
  <li>Apple</li>
  <li>Banana</li>
  <li>Mango</li>
</ul>

If Mango is removed, Virtual DOM compares old vs new trees and tells React: only remove the Mango item, not the entire <ul>.

Virtual DOM helps:

  • 🧩 Avoid unnecessary updates
  • ⏱️ Improve rendering speed
  • 📉 Reduce browser paint cycles

📌 Conclusion

The Virtual DOM is a key reason why React is fast and scalable. It allows efficient UI updates by avoiding direct manipulation of the real DOM and only applying the necessary changes after diffing. It brings a smart and declarative way to build user interfaces.

📌 Component: EmployeeForm.jsx

import React, { useState } from "react";
import axios from "axios";

export default function EmployeeForm() {
  const [employee, setEmployee] = useState({ name: "", email: "", age: "" });
  const [errors, setErrors] = useState({});
  const [success, setSuccess] = useState("");

  const handleChange = (e) => {
    const { name, value } = e.target;
    setEmployee({ ...employee, [name]: value });
    setErrors({ ...errors, [name]: "" });
    setSuccess("");
  };

  const validate = () => {
    const newErrors = {};
    if (!employee.name.trim()) newErrors.name = "Name is required";
    if (!employee.email.trim()) newErrors.email = "Email is required";
    else if (!/\S+@\S+\.\S+/.test(employee.email)) newErrors.email = "Invalid email format";
    if (!employee.age.trim()) newErrors.age = "Age is required";
    else if (isNaN(employee.age)) newErrors.age = "Age must be a number";
    setErrors(newErrors);
    return Object.keys(newErrors).length === 0;
  };

  const handleSubmit = async (e) => {
    e.preventDefault();
    if (!validate()) return;

    try {
      await axios.post("https://your-api.com/employees", employee);
      setSuccess("✅ Employee saved successfully!");
      setEmployee({ name: "", email: "", age: "" });
    } catch (err) {
      setSuccess("❌ Failed to save employee. Please try again.");
    }
  };

  return (
    <div className="container mt-4">
      <h4>Add New Employee</h4>
      {success && <div className={`alert ${success.includes("✅") ? "alert-success" : "alert-danger"}`}>{success}</div>}
      <form onSubmit={handleSubmit}>
        <div className="mb-3">
          <label className="form-label">Name</label>
          <input type="text" name="name" className={`form-control ${errors.name ? "is-invalid" : ""}`}
            value={employee.name} onChange={handleChange} />
          <div className="invalid-feedback">{errors.name}</div>
        </div>

        <div className="mb-3">
          <label className="form-label">Email</label>
          <input type="email" name="email" className={`form-control ${errors.email ? "is-invalid" : ""}`}
            value={employee.email} onChange={handleChange} />
          <div className="invalid-feedback">{errors.email}</div>
        </div>

        <div className="mb-3">
          <label className="form-label">Age</label>
          <input type="text" name="age" className={`form-control ${errors.age ? "is-invalid" : ""}`}
            value={employee.age} onChange={handleChange} />
          <div className="invalid-feedback">{errors.age}</div>
        </div>

        <button className="btn btn-primary" type="submit">Save</button>
      </form>
    </div>
  );
}

📌 1. What are Hooks?

Hooks are functions that let you "hook into" React state and lifecycle features from functional components. Introduced in React 16.8, they replaced the need for class components in most cases.

📌 2. Why Hooks?
  • 🔁 Use state in functional components
  • 🧠 Reuse logic across components (via custom hooks)
  • 🧼 Cleaner and more readable code (no `this` keyword)
📌 3. Common React Hooks
  • useState – For state management
  • useEffect – For side effects (API calls, subscriptions)
  • useContext – Access context values
  • useRef – Persist data between renders (non-re-render)
  • useMemo / useCallback – Performance optimization
📌 4. Example: useState + useEffect

import React, { useState, useEffect } from 'react';

function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => setCount(c => c + 1), 1000);
    return () => clearInterval(id);
  }, []);

  return <p>Timer: {count}</p>;
}
📌 Conclusion

Hooks simplify React development by removing the need for class components and making stateful logic reusable across functional components.

📌 1. useState – What It Does

useState lets you add state to functional components. It returns a state variable and a function to update it.


const [value, setValue] = useState(initialValue);

React remembers this state between renders and updates the UI when setValue() is called.

📌 2. useEffect – What It Does

useEffect is used for side effects: data fetching, timers, subscriptions, DOM manipulation, etc.


useEffect(() => {
  // runs after render
  return () => {
    // cleanup (optional)
  };
}, [dependency]);
📌 3. useEffect Behavior
  • Runs after every render by default
  • If you pass [], it runs once like componentDidMount
  • If you pass dependencies, it re-runs only when they change
📌 4. Example with Timer

useEffect(() => {
  const id = setInterval(() => setCount(c => c + 1), 1000);
  return () => clearInterval(id); // cleanup
}, []);
📌 5. Common Mistakes
  • ❌ Forgetting dependencies in the array
  • ❌ Infinite loop due to wrong dependencies
  • ✅ Use cleanup to avoid memory leaks
📌 6. When to Use Each
  • useState: Storing user input, toggles, counters
  • useEffect: Fetch data from API, attach event listeners, set timers
📌 Conclusion

useState and useEffect are the two most essential hooks in React. Together, they allow components to manage internal state and perform actions after rendering, replacing the need for lifecycle methods in class components.

📌 1. What is a Component in React?

A component in React is a reusable piece of UI. Every React app is built using components — either function or class based.

They can accept inputs called props and return React elements describing what should appear on screen.

📌 2. Functional Component (Stateless)

function Welcome(props) {
  return <h1>Hello, {props.name}!</h1>;
}
📌 3. Class Component (with State)

A class component lets you use state and lifecycle methods like componentDidMount. You must extend React.Component.


import React from 'react';

class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = {
      count: 0
    };
  }

  increment = () => {
    this.setState({ count: this.state.count + 1 });
  }

  render() {
    return (
      <div>
        <p>Count: {this.state.count}</p>
        <button onClick={this.increment}>Increment</button>
      </div>
    );
  }
}
📌 4. How to Set State in Class Component
  • ✅ Use this.setState()
  • ✅ Never mutate state directly (e.g., this.state.count = 5 ❌)

this.setState({ key: newValue });
📌 5. When to Use Class Components?

Before Hooks (React 16.8), class components were required for state and lifecycle. Now we use class components if:

  • 💼 You’re working in older codebases
  • ⏳ You need lifecycle methods and can’t refactor to hooks yet
  • 📘 For learning purposes to understand React's evolution

📌 Conclusion

React supports both class and function components. Class components use traditional state and lifecycle methods, while function components with Hooks are now the modern standard for building efficient, cleaner UIs.

📌 1. Simpler Syntax

Functional components are just JavaScript functions. There's no need for constructors, this keyword, or binding methods.


// Functional
function Greet() {
  return <h1>Hello!</h1>;
}

// Class
class Greet extends React.Component {
  render() {
    return <h1>Hello!</h1>;
  }
}
📌 2. Hooks Make Functional Components Powerful

With the introduction of Hooks (like useState, useEffect, useContext), functional components can do everything class components can — and more!


const [count, setCount] = useState(0);

useEffect(() => {
  console.log("Component mounted or updated");
}, [count]);
📌 3. No More ‘this’ Confusion

In class components, forgetting to bind this or misusing it is a common source of bugs. Functional components avoid this entirely.


// ❌ In class component
this.handleClick = this.handleClick.bind(this);
📌 4. Better Code Reusability (Custom Hooks)

Custom hooks let you extract and reuse stateful logic across components, which is harder in class-based code.


// useOnlineStatus.js
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(true);
  // logic...
  return isOnline;
}
📌 5. Cleaner Lifecycle Management

Functional components with useEffect let you combine multiple lifecycle operations in a single place. In class components, you'd need multiple methods like:

  • componentDidMount
  • componentDidUpdate
  • componentWillUnmount
📌 6. Performance Benefits

React can optimize functional components better in some cases. Also, they tend to use less boilerplate code, leading to faster development and smaller bundles.

📌 7. Preferred by React Community
  • ✅ React Docs recommend using functional components
  • ✅ Most modern libraries and examples use Hooks
  • ⚙️ Easier integration with tools like Redux Toolkit, React Query, etc.

📌 1. What is a Lifecycle in React?

The React lifecycle represents the different stages a component goes through from creation to destruction. You can tap into these stages to run your code (API calls, cleanup, etc.).

📌 2. Three Main Phases
  • Mounting – Component is created and inserted into the DOM
  • Updating – State or props change, triggering re-render
  • Unmounting – Component is removed from DOM
📌 3. Lifecycle Methods in Class Components

class Example extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
    console.log("Constructor");
  }

  componentDidMount() {
    console.log("Component mounted");
  }

  componentDidUpdate(prevProps, prevState) {
    console.log("Component updated");
  }

  componentWillUnmount() {
    console.log("Component will unmount");
  }

  render() {
    return <p>Count: {this.state.count}</p>;
  }
}
📌 4. Functional Equivalent using useEffect

import { useState, useEffect } from 'react';

function Example() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("Mounted");

    return () => {
      console.log("Cleanup before unmount");
    };
  }, []);

  useEffect(() => {
    console.log("Updated count:", count);
  }, [count]);

  return <p>Count: {count}</p>;
}
📌 5. Comparison Table
Lifecycle Stage Class Component Functional Component
Mount componentDidMount() useEffect(..., [])
Update componentDidUpdate() useEffect(..., [deps])
Unmount componentWillUnmount() return () => {...} inside useEffect
📌 6. Key Notes
  • 👨‍🏫 Functional components can handle all lifecycle stages using useEffect
  • 🔥 Multiple useEffect() can be used for different concerns
  • 🧹 Cleanup functions in useEffect act like componentWillUnmount

React lifecycle allows you to perform operations during key moments in a component's life. In modern React, useEffect gives full control over lifecycle behavior in functional components — making class methods mostly obsolete in new codebases.

📌 1. What are Hooks?

Hooks are special functions introduced in React 16.8 that let you use React features (like state, lifecycle, context) in functional components.

📌 2. Basic Hooks
  • useState – Add local state
  • useEffect – Side effects like API calls, subscriptions
  • useContext – Access context without wrapper
📌 3. Additional Hooks
  • useReducer – Complex state management (like Redux)
  • useCallback – Memoizes a function between renders
  • useMemo – Memoizes a calculated value
  • useRef – Mutable reference that doesn’t cause re-render
  • useImperativeHandle – Customize the instance exposed by ref
  • useLayoutEffect – Like useEffect, but fires before paint
  • useDebugValue – Debugging custom hooks
  • useTransition – Optimize state transitions (React 18+)
  • useDeferredValue – Defer re-renders for expensive updates
  • useId – Generate unique IDs (React 18+)
  • useSyncExternalStore – Subscribe to external store safely
  • useInsertionEffect – Inject styles before layout (rare)
📌 4. When to Create a Custom Hook?
  • ♻️ Repeating same logic in multiple components
  • 🧼 Want to keep components clean and readable
  • 🔌 Need to isolate and reuse side effects
📌 5. How to Create a Custom Hook

Custom hooks are just JavaScript functions that start with use and can use other hooks inside.


// useWindowWidth.js
import { useState, useEffect } from 'react';

function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', handleResize);

    return () => window.removeEventListener('resize', handleResize);
  }, []);

  return width;
}

export default useWindowWidth;
📌 6. Using Custom Hook

import useWindowWidth from './useWindowWidth';

function Layout() {
  const width = useWindowWidth();
  return <p>Window width: {width}px</p>;
}
📌 7. Rules of Hooks
  • ✅ Always call hooks at the top level (not inside loops/conditions)
  • ✅ Only call hooks from React functions (or custom hooks)
  • ✅ Custom hook names must start with use
📌 Conclusion

React provides a rich set of built-in hooks for most needs. When logic repeats across components, building a custom hook makes code cleaner and reusable. All hooks follow strict rules to ensure predictable behavior.

📌 1. What is useMemo?

useMemo is a React Hook that caches a computed value so it doesn't have to be recalculated on every render.


const expensiveValue = useMemo(() => {
  return computeHeavyOperation(data);
}, [data]);

✅ Useful for performance optimization when computations are heavy or complex.

📌 2. What is useCallback?

useCallback returns a memoized version of a callback function that only changes if one of the dependencies changes.


const handleClick = useCallback(() => {
  console.log('Clicked!');
}, []);

✅ Useful when passing callbacks to child components to avoid unnecessary re-renders.

📌 3. Key Difference
  • useMemo – Caches the result of a function
  • useCallback – Caches the function reference itself
📌 4. Side-by-Side Example

const memoizedValue = useMemo(() => expensiveFunction(a, b), [a, b]);

const memoizedCallback = useCallback(() => {
  doSomething(a, b);
}, [a, b]);
📌 5. Real Use Case Example

function Parent() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  const expensiveCalculation = useMemo(() => {
    console.log("Calculating...");
    return count * 2;
  }, [count]);

  const handleChange = useCallback((e) => {
    setText(e.target.value);
  }, []);

  return (
    <div>
      <h4>Double Count: {expensiveCalculation}</h4>
      <input onChange={handleChange} value={text} />
    </div>
  );
}
📌 6. When to Use?
  • 🧠 Use useMemo when:
    • Heavy calculations
    • Prevent re-computing values unnecessarily
  • 🧠 Use useCallback when:
    • Passing functions to child components
    • Prevent function recreation on every render
📌 7. Visual Summary
Hook What It Caches Use Case
useMemo Return value of function Expensive calculations
useCallback Function reference Prevent re-rendering children
📌 Conclusion

Both useMemo and useCallback are performance optimization hooks. Use them only when necessary, such as for expensive computations or preventing unnecessary re-renders of child components that rely on stable function references.

📌 1. What is React Fiber?

React Fiber is the **complete rewrite of React's core algorithm**, introduced in React 16. It enables **incremental rendering**, **better performance**, and **prioritization** of UI updates. Unlike the older stack-based algorithm, Fiber uses a **linked list structure** for better control over work units.

📌 2. Goals of React Fiber
  • 🔁 Incremental rendering (split rendering work into chunks)
  • 🎯 Prioritize updates based on urgency (like animations vs. data fetch)
  • ⏸️ Pause, resume, and restart work as needed
  • 🔄 Concurrency and smooth rendering under load
📌 3. How Fiber Works Internally

Fiber breaks down rendering into a tree of units of work. It uses a **work loop** to perform updates incrementally, allowing the browser to do other work in between (like user input or animations).


function workLoop(deadline) {
  while (nextUnitOfWork && deadline.timeRemaining() > 1) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
  }
  if (!nextUnitOfWork && workInProgressRoot) {
    commitRoot();
  }
}

This allows React to split work across multiple frames for smooth rendering.

📌 4. Fiber Node Structure

Each Fiber node represents a component and contains information like:

  • type – Component type
  • stateNode – DOM node or class instance
  • child, sibling, return – For traversing the tree
  • pendingProps, memoizedProps – For props comparison
📌 5. Phases of Fiber

React Fiber has two main phases:

  1. Render Phase: Work is done on a copy of the Fiber tree (non-blocking)
  2. Commit Phase: Final DOM updates are committed (blocking)
📌 6. Reconciliation with Fiber

During reconciliation, React compares new elements with old ones and determines what to update, remove, or add. Fiber allows this to be done **asynchronously**, improving performance for large trees.

📌 7. Scheduling and Priority

React Fiber uses an internal priority system based on **"lanes"**, where:

  • High-priority tasks like input get processed first
  • Low-priority tasks (like logging) can be deferred
This makes React highly responsive under load.

📌 8. Concurrency with Fiber

Fiber is the foundation for **Concurrent Mode** in React. It enables:

  • Suspense for data fetching
  • Time-slicing (pausing work mid-way)
  • Better responsiveness for high-priority updates

📌 9. Real-World Benefits

With Fiber, React apps:

  • Feel smoother with animations
  • Don't block user interactions while rendering
  • Handle complex UIs better

Each of these becomes a "Fiber" node linked together for reconciliation and updates.

📌 Conclusion

React Fiber is a powerful re-architecture of the core React rendering engine. It improves responsiveness, enables concurrency, and lays the groundwork for modern React features like Suspense and Concurrent Rendering. It’s a core part of what makes React performant today.

📌 What is Concurrent Mode?

Concurrent Mode is an advanced feature in React that helps make your app more responsive by rendering components *without blocking the main thread*. It allows React to pause, abort, or restart rendering work as needed.

📌 Key Benefits
  • 🚀 Improves performance for large, complex UIs
  • 💡 Enables better user experience by avoiding blocking interactions
  • 🔁 Supports features like **Suspense**, **Transitions**, **startTransition**, etc.
📌 Real World Example

In heavy UI apps (like search filters), React can skip unnecessary renders and prioritize important updates like input typing.

📌 Example: startTransition

import { startTransition, useState } from "react";

function SearchBox() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);

  const handleChange = (e) => {
    const val = e.target.value;
    setQuery(val);
    startTransition(() => {
      const filtered = fetchData(val); // heavy filtering logic
      setResults(filtered);
    });
  };

  return (
    <input value={query} onChange={handleChange} />
  );
}
📌 Core APIs Enabled by Concurrent Mode
  • startTransition()
  • useDeferredValue()
  • Suspense for data fetching
  • useTransition()
📌 Important Notes
  • 🚧 You don’t manually “enable” Concurrent Mode anymore in React 18+ — it's **built-in by default**
  • 🔍 Concurrent rendering is **not guaranteed**, it's **opportunistic** — React does it when needed
📌 Conclusion

Concurrent Mode helps React stay fast and fluid by making rendering interruptible. It's most useful in large apps with dynamic filtering, transitions, and real-time updates.

📌 What is Reconciliation?

Reconciliation is the process by which React updates the **DOM** when the **state or props** of a component change. It compares the new Virtual DOM tree with the previous one and applies the minimal number of changes to the real DOM.

📌 How It Works
  • 🧠 React maintains a Virtual DOM
  • 📤 When state/props change, a new Virtual DOM is created
  • 🕵️‍♂️ React compares the new Virtual DOM with the old one
  • 🔧 Only the changed elements are updated in the real DOM
📌 Key Algorithm: Diffing

React uses a **diffing algorithm** with these assumptions:

  • 📦 Elements of different types produce different trees
  • 🔁 You can hint React with a key prop to optimize reconciliation for lists
📌 Example

// Initial render
<ul>
  <li key="1">A</li>
  <li key="2">B</li>
</ul>

// After update
<ul>
  <li key="2">B</li>
  <li key="3">C</li>
</ul>

🔑 Using key helps React move/update elements correctly without re-rendering the whole list.

📌 Optimizations React Uses
  • 🧬 Component-level re-rendering only if props/state change
  • 🔁 Skips subtrees if component returns same result
  • 🚀 React.memo and PureComponent help skip unnecessary renders
📌 Real-World Tip

Always use key for list items. Avoid using index as key unless list never changes.

📌 Conclusion

Reconciliation makes React efficient by updating only the parts of the DOM that changed. This allows for fast and scalable UI updates even with complex components.
